# 目視確認HTMLの比較表示修正

PR #135後続の表示修正。原画像とmaskが離れ、英語名だけでは範囲を判断しにくかったため、
各maskを「写真＋輪郭線／二値mask」の2列区画にした。
正式な提示物の再生成・置換と本番DBへの提示登録はまだ行っていない。

## 表示と定義

- 左にmaskと同じ解析座標の写真と透明PNGの輪郭、右に白黒maskを配置する。
  輪郭の画素以外は透明で、写真へ塗りを重ねない。人物にも同じ配置を使う。
- 写真は番号ごとに1回だけ埋め込み、各区画の背景として再利用する。
  取得画像は番号冒頭の開閉欄から別に参照できる。
- 日本語名・英語code・処理上の定義を各maskの横とページ冒頭の凡例表に置く。
  原判定のcodeは保持し、人物・主体・上空写真・理由等に日本語を併記する。
- 容量上限は12,500,000 byte。凡例も含めて分割し、通し番号と各ページの保持対象を維持する。
  新しい表示画像には埋込byteのSHAを付ける。入力・提示run・原画像SHAの契約は変えない。

根拠は[region-policy-v1](../../docs/region-policy.md)、
[親対応表v2](../../docs/region-parents-v2.md)、`region_policy.PARENTS/ALLOW`、taxonomy、
既存の画像ゲートschema・判定分岐。訳語と説明は`mobile_labels.py`にまとめた。
親クラスの許容を、部位の正解や品質合格という説明に置き換えない。

raw候補は親領域の制約前。有効maskは候補と許容親領域の共通部分から空・人物・異roleの競合を除く。
同じ親role内の壁3種、幹・樹冠は和集合。人物maskはsemantic person全画素で、
実在人物の画像判定との一致を保証するものではない。

既存文書に細分条件・範囲の説明がないものは「定義未記載」とした。
一覧は`wall_main`、`wall_secondary`、`gable_wall`、`eave`、`cornice`、`accent_other`。
未知ラベルも定義を推測せず表示する。今回の4ページに出る17有効role・除外・人物の処理定義に欠落はなかった。

### レビューP2：除外理由の集合

`semantic_mismatch`の「有効roleに残らない候補画素」という説明を修正した。
所属数は、親制約を適用して同親候補を和集合にした後、競合を除去する前のrole数。

- `semantic_mismatch`：raw候補かつ所属数0。空・人物・競合は含まない。
- `conflict`：所属数2以上。同じ親role内の和集合は競合に数えない。
- `void`：所属数1以外の全画素。候補外・空・人物・競合も含む。

`sky`・`person`の全semantic画素、raw候補と有効mask、各roleの親制約も実装と照合した。
ほかの集合のずれはなく、`conflict`と`void`は数条件を明記した。
空・人物・候補外・親不一致・異role競合・同親和集合を含む合成入力で、
実際の`region_policy.constrain`の集合と凡例・区画の説明を照合する回帰テストを追加した。
