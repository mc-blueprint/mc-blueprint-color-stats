## 返信後の取込み

ユーザーへの依頼例：
「全138枚確認済み。問題なし」または「全138枚確認済み。問題あり：7 人物見落とし、85 主体が違う」。
全枚数を確認したことが不明なら、承認せず確認完了の返信を待つ。

ユーザーは自由に返信してよい。オーケストレータが返信原文を私有領域に保持し、
全件確認・問題番号・理由を確認してから、次の定型UTF-8テキストへ変換する。
ユーザー自身に定型書式やJSON作成を要求しない。

```text
全138枚確認済み
問題なし
```

問題がある場合は、1行に1件ずつ記載する。

```text
全138枚確認済み
7: 人物見落とし。右端に人物が 2 人写っています
85: 人物maskは問題ないが主体が違う
```

改行はLF・CRLFのどちらでもよく、空行は無視する。
1行目は提示件数と一致する「全N枚確認済み」（末尾の句点は任意）。
以降は「問題なし」の1行だけ、または「番号: 理由」の行だけにする。
件数・行頭番号は全角数字も可、コロンは半角・全角とも可。番号は1〜N・重複なし・理由必須。
理由中の数字・句読点・「番号 7」「問題ない」「未確認」などの語は解釈せずそのまま保持する。
否定形の1行目、件数不一致、書式違反、空でない余分な行は拒否する。
自由文の「7 人物が 2 人写っている」は担当が「7: 人物が 2 人写っている」へ変換し、
「番号 7」も確認したうえで行頭の「7:」へ変換する。取込み側は自由文を推測しない。

確認者名は「ユーザー」で固定する。番号表・元manifest・全自動判定のSHAが一致する場合だけ変換する。
現行コードを配置した検証済み環境で、次のコマンドを記録付きで実行する。
入力・出力は私有領域の絶対パスとし、出力は未使用のファイル名にする。

```sh
python -m bench.issue114.mobile reply \
  --execution /非公開の絶対パス/execution \
  --mapping /非公開の絶対パス/mobile/number-map.json \
  --input /非公開の絶対パス/chat-reply.txt \
  --output /非公開の新規絶対パス/converted-review.json
```

既定は変換のみでDB接続なし。内容を返信原文と照合した後、同じ引数に`--apply`を付け、
`--output`を別の未使用ファイル名へ変えて実行すると、#119の`privacy_review.record_hold`と
`privacy_review.write`で追記する。本番反映には別途実行許可が必要。
今回は返信前なので変換・反映とも実行していない。

問題番号は人の判定でpendingとし、理由・確認者・以前の判定履歴を保存する。
残りの**提示画像だけ**は人の確認済みとし、自動判定の採否・subject・maskを維持する。
未提示2,462枚を目視済みと記録せず、提示画像内の元pendingも採用へ昇格させない。
変換した定型テキスト・対応表hashは出力JSONへ残す。ユーザーの返信原文は私有領域に別途保持する。
問題が1件でもあれば統計承認を出さず、該当画像の修正・再解析方針を決める。
問題なしの場合も既存の全件状態照合と承認ゲートを通り、統計は別の許可済み段取りで実行する。
