# 非公開HTMLによる目視確認

#122/#114の再開時は[単独GPUの再開手順](production-restart.md)に従い、
母集団・seed・合格条件を表示前に固定する。

#120は既存の`bench.issue114.mobile`とA/B/Cの契約を拡張する。
画像・番号とassetの対応表・所見はすべてGit外のprivate領域に保存する。
HTMLを会話でユーザーへ送り、全提示画像の確認済みと問題番号・理由だけを返信してもらう。
ユーザー自身によるJSON作成・返送やWindows操作は不要。

## 提示物

`mobile build`は保持ロック下で対象の利用期限、現行のimage-review-v1、region-policy-v1、
privacy-review-v2を照合する。保留runも提示できるが、訂正前・旧policy・根拠が変わったrunは拒否する。
判定台帳は増やさず、既存のProcessingRunとProcessingRunInput、保持台帳を使用する。

```sh
python -m bench.issue114.mobile build \
  --execution /非公開の絶対パス/execution \
  --bundle /非公開の絶対パス/review-bundle \
  --taxonomy /実行コードの絶対パス/taxonomy \
  --output /非公開の新規絶対パス/mobile \
  --view comparison
```

- `--view raw`は原画像だけを提示し、個別の自動判定・予測maskをHTMLに含めない。
  番号表は私有のままA/B/Cへの参照と確認方法を保持する。
- `--view comparison`は原画像と予測を区別し、写真＋透明輪郭、各クラスの白黒maskを縦1列で表示する。
  写真の色とmaskの塗り色を混ぜない。建物・地形・空・人物・競合・voidは名前・説明・線種で区別する。
  個別の区分、元の採否・subject、画像側人物判断、人物方針による採否、版、除外理由を表示する。
- rawでも、別の提示で予測を見た場合は完全盲検とは扱わない。
- 取得画像はAssetの保持対象ファイルをbyte・解像度そのままで埋め込み、A/Cの取得SHAと照合する。
  旧bundle内の再符号化PNGを提示済み原画像SHAの代わりにしない。
- MPOも元byte列のままJPEGとして埋め込み、A・prep/B・Cと同じ先頭フレームを提示する。
  AはEXIFの向き補正を行い、prepは行わないため、MPOのOrientationが未指定または1の場合だけ
  受け付ける。回転・反転指定のあるMPOは生成・配信検証とも拒否し、変換や標本差替えで通さない。
- maskと輪郭は解析入力と同じ座標のPNG、表示は無補間。輪郭以外の画素は透明で写真を隠さない。
- 固定無作為群を先に、残りのchallenge群を後に提示する。標本項目数とユニークな提示画像数を分ける。
  別assetでも取得SHAとbyteが同じ原画像は、1番号・原画像1回へまとめる。
  その番号の中に各項目の比較区画を残し、すべての区画を確認する。代表項目だけで他項目を確認済みにしない。
  番号表は`issue114-mobile-v2`の項目別`rows`に同じ`number`を保持する。原画像SHA・各項目の参照は省略しない。
  HTMLと番号表の項目対応も照合する。変更前のHTML・番号表は再生成し、旧版へのフォールバックはしない。
  番号表に`template: issue173-mobile-v1`と項目別の`presentation`（表示値・原画像・解析画像・
  mask・輪郭のdata URIとSHA）を保存する。番号表にも画像byteが含まれるため、HTMLと同じ保持対象とする。
  生成と配信・返信の検証は同じ固定テンプレートを使い、入力から期待するファイル全体を再生成する。
  対象HTMLとのbyte完全一致を要求し、部分的な正準HTMLや文字位置の切り出しによる照合はしない。
  内容欠落・画像差替え・非表示属性・自己終了タグ・1 byteの改変も、ファイルSHAを付け直して通さない。
  再生成用の画像SHA・実復号・上限も照合する。表示テンプレートを変更するときは版を更新する。
- 各ファイルの上限は既存の12,500,000 byte（Issueの25MB以下）。可能なら容量を均等に2分割し、
  必要ならさらに分割する。通し番号は維持する。原画像1件だけで上限を超える場合は生成を拒否する。
- 全画像とCSS背景を実復号し、埋込SHA・実byte容量・連番・外部参照なしを検証する。
  CSPも外部通信・スクリプトを許可しない。原画像を含むHTMLと番号表はページごとの構成assetへ保持登録する。
- リポジトリ内への生成・共有コピー・返信JSON保存は拒否する。
  共有HTML・tar・画像・個別結果をGitへ追加しない。

## 共有コピーと保持

```sh
python -m bench.issue114.mobile share \
  --bundle /非公開の絶対パス/mobile \
  --output /非公開の新規絶対パス/delivery
```

生成元の容量・SHA・埋込画像・番号を照合し、新しいHTMLコピーと番号表、`review.tar`を作る。
tarへ入れるのはHTMLだけで、番号とassetの対応表は送付しない。
全出力を既存の`image_bundle`として保持登録する。コピー・tarの構成画像が失効したら、
既存cleanupが当該共有束を削除する。登録失敗時は今回の新規出力だけを取り除く。
別hostへ転送したコピーも、実際の転送先host/pathを同じ保持台帳へ登録する必要がある。
このコマンドは実行端末でコピーと登録を行い、遠隔転送は行わない。
ページの構成項目は、各rowの`number`がファイルの`first`～`last`に入る全項目とする。
同じ番号の項目が複数あるため、rowsの位置をスライスして保持登録対象を選ばない。

## 番号返信

オーケストレータはユーザーの返信原文をprivateに残し、全件確認・番号・理由を確認した後、
既存の定型テキストへ変換する。書式・全角数字・不備の扱いは
[既存の番号返信手順](../bench/issue114/mobile-review.md#返信後の取込み)と同じ。

```text
全2枚確認済み
1: 人物の見落とし
```

`mobile reply`は従来と同じ引数を使う。送付した`--mapping`の隣に実際のHTMLを置く。
取込み前にHTMLのSHA・全番号、番号表、固定review manifest、元の自動判定SHAを照合する。
返信変換も必ず全体再生成を照合する。配信ディレクトリを省略した場合はreview manifestの隣を使う。
未完了・範囲外・重複番号・理由なし、順序入替え、固定manifestや提示物の変更は拒否する。
返信の「全N枚」のNは提示番号数で、標本項目数ではない。同じ番号の問題有無・理由を全構成項目へ展開する。

`--apply`を付けない変換はDB接続なし。付けた反映は既存の`privacy_review.record_hold/write`を使い、
問題番号は理由付き保留、残りの提示画像だけを確認済みの別runへ追記する。
元run・qualityは上書きせず、既存の人物訂正・human hold・policyによる保留を解除しない。
元runに依存した解析・統計承認の再利用はCの既存検証で拒否する。未提示の画像には書き込まない。

## 未提示の保留

review manifestの`required_ids`は提示した全項目、`sampling.required_ids`は元の固定標本全体を維持する。
`nonpresented_holds`には`asset_id`と現在有効な`privacy_review_run_id`を記録する。
固定標本は提示項目と未提示保留の非交和に一致しなければならない。重複・交差・欠落・余分を拒否する。
未提示の参照には同じ対象の現行human hold・pending・確認者・理由が必要で、自動のpolicy保留だけでは代替しない。
未提示保留に確認済みの返信や新しい確認runを作らず、統計でも採用対象へ数えない。

## 確認範囲

この表示は標本の品質合格や本番承認を代行しない。標本・見落とし基準はDで固定する。
本番での生成・共有登録・返信反映は本番DBの書込みを伴うため、許可された作業として別途行う。
#120の実装検証では、ローカルWSLの隔離DBと生成画像だけを使用する。
スマートフォンでの表示確認は、privateの確認用モックHTMLを会話で送った後にユーザーが行う。
ユーザーの確認が済むまで、その完成条件は未完了として扱う。
