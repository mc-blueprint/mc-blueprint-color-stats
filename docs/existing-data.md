# 既存データの補完と収集目標

Issue #105 は #104 の固定 snapshot と成功 rule_stat を基準にする。
本番の根拠・実行記録・比較は [bench/issue105/results.md](../bench/issue105/results.md) に置く。
反証指摘を修正した現行版は [訂正v2の結果](../bench/issue105/correction-v2/results.md) を参照する。
画像・原 meta・個別の撮影属性台帳は内部領域だけに保存し、配布しない。

## 保存済み根拠の補完

`colorstats.stats.supplement.execute` は #72/#99 の `infer` を再利用する。
保存済みの固有カテゴリと名称・位置などの独立根拠が必要であり、名称一致や検索意図だけでは
subject を確定しない。#105以前の確定値・他runの値と既存の関連付けは保持する。
`correction_runs`には訂正を許可された成功runだけを指定し、保存計画とDBの所有権を属性単位で
照合する。自身の先行推定はpreservedで固定せず、全根拠を同時に読み直して矛盾時はunknownへ戻す。
本反映には dry-run の計画 hash を渡す。dry-run の取引は READ ONLY である。

季節は Commons の季節カテゴリ、または撮影日と緯度から推定する。
日付は一意の日を指定したEXIF/ISO形式だけを受理し、期間・年/月だけ・近似・説明付き表記は
開始日を抜き出さずunknownにする。保存metaは`DateTimeOriginal.source=exif`、またはEXIF撮影日との
一致がある場合だけ撮影日として使う。`commons-desc-page`やアップロード日時だけでは根拠にしない。
保存日付とEXIFの候補日が食い違う場合もunknownにする。
緯度による推定は回帰線と極圏の間に限る。北半球は12〜2月を冬、3〜5月を春、
6〜8月を夏、9〜11月を秋とし、南半球は半年ずらす。これは撮影時の季節区分の推定であり、
植物の紅葉・積雪・局地的な季節現象の証明ではない。熱帯・極域・位置不明は推定しない。

時間帯は時刻を明示するカテゴリ、または EXIF の GPS UTC / 撮影日時と時差を使う。
時差不明の撮影日時やアップロード日時を UTC とみなさない。
GPS UTCだけ、または撮影日時＋時差だけなら、その一方を根拠にする。両方あればUTCへ変換して
照合し、丸め幅1秒を超える違いがあれば`conflicting_utc_evidence`でunknownとする。
撮影日時内の埋込み時差と別タグの時差も、存在するものをすべて照合する。
片方が不正な表記の場合も、もう片方を選んで続行しない。GPS取得時刻の遅延を推測で補正しない。
UTC・GPS から均時差と太陽赤緯を年周近似し、太陽高度1度超をday、-7度未満をnightとする。
-5〜-1度は市民薄明の内部として、極域を除き南中前をdawn、後をduskとする。
境界の1度幅は近似誤差を避ける保留帯であり unknown のまま残す。
同じ属性について独立根拠が矛盾するときも、新しい値を付けない。
絵画・描画等を示す保存カテゴリは実景の撮影属性に使わない。決定的50件の元画像・説明・EXIFを
照合したカテゴリ監査では誤り3/50（6%）、保留2件を記録した。保留を正解に数えない。

EXIFを別ホストで読む場合は実画像のSHAを検証し、SHAをキーとする台帳を渡す。
大きな画像や壊れた EXIF で Pillow が読取りを拒む場合は保留し、安全制限を解除しない。
推定値・state・根拠、保持した以前の推定記録を成功 run と新規 snapshot に残す。
地域・年代は #85 の有効 claim の全一致規則を地形にも適用する。
キャッシュにない項目を推測せず、Wikidata の通信は行わない。

属性補完runは #85 の地域・年代根拠と同様に、画像解析の権利判定から分離する。
統計の `subject_attribute_run_ids` は地域・年代runに加えて保存済み属性補完runを含む。
入力辺と成功runの照合は維持し、画像自身の権利・解析モデル重みのゲートは緩めない。
複数画像の属性根拠をまとめたrunの区分で、別の適格画像まで除外しないための区別である。

## 不足一覧の再生成

固定した report と snapshot、同じ統計設定・taxonomy を使う。

```sh
python -m colorstats.stats.deficits \
  --report /絶対パス/report/report.json \
  --snapshot /絶対パス/snapshot \
  --output /未使用パス/deficits.json
```

taxonomyの全37建築役割・全12地形役割について、paletteと異なる2役割の全無向pairを
条件別・12目標層別に列挙する。reportにない未観測・未検証pairも省略しない。
役割ゲートの10 subjectと直接分布の30 subject・n_effの不足を区別する。
層別palette・relationも既存の点観測と部分層補正を使い、未観測のpairを0で残す。
snapshotを指定しない場合の層別n_effは未計測（null）であり、0件の実測とは区別する。
属性不足・subject不足・部位不足・権利除外は重複し得るため、原因別件数は合計しない。
部位不足にはモデル未検証、和集合色の未保存、解析後の採用漏れが含まれ、
画像追加だけで解決できるとは限らない。層の支持は未知属性の周辺化を含み、実測所属と区別する。

## #92・#94・Commonsへの引継ぎ

`configs/collection_targets.yaml` が共通の収集目標である。
`priority` は小さい順、`images` は既存画像を含む層の総枠、`collection_sources` は優先供給元、
`focus_parts` は確認したい部位を表す。層内のpair不足は `gap_plan.deficits` を参照する。
既存Commonsの計画は `images` に対する不足率順なので、枠の再配分が優先順にも反映される。
`priority` と供給元・部位の指定は #92・#94 が計画を作る際の共通入力とする。
`subjects` は統計の目標比率を定めるため維持し、収集枠の調整で統計の事前比率を変えない。

総枠は10,000枚、subjectあたり3枚・0.3%、作者5%、供給元80%、地域40%を維持する。
同じ対象の別画像を増やすより、権利と属性を確認できる新しい対象を優先する。
Commonsは全体8,000枚と層ごとの80%の両方を守り、LoC・Mapillaryの分を
Commonsへ振り替えて上限を緩めない。統計の適格7,607画像と収集台帳の既存件数は区別し、
実行時には除外画像も含む最新の台帳から残枠を再計算する。

中国の住宅と秋の森林を優先度1にする。建築はwall・roof・window・doorとその共起、
地形はtreeと岩・草・砂・雪との共起を対象にする。モデルで未検証の部位は統計へ採用せず、
部位評価・色観測の改善が別途必要である。
LoC（#92）は北米の年代根拠を持つ住宅、Mapillary（#94）は街路から同定できる建築と
撮影日時・位置を持つ地形、Commonsは固有カテゴリと季節・時刻を確認できる対象を優先する。
供給元の追加実装は各Issueの範囲で行う。#105ではcollect/・analyze/prep・source_policyを変更しない。
