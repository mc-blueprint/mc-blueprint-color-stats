# M2ベンチマーク集計と採用判断（Issue #47）

2026-11-03。集計基準は`feature/issue-47`の起点`6196fcb`（引継ぎ済みの`origin/develop`）。
既存評価の集計に加え、収集画像の実運用読取りと固定500 assetの性能計測を行った。
手法の採用契約は[設計 §5.2・§8・§10](design.md)、個々の実測・評価条件は以下の参照先を正本とする。

## 1. 採用判断

| 対象 | M2での決定 | 根拠と制約 |
| --- | --- | --- |
| 分割 | `sam2-dino`：SAM 2.1 hiera tiny＋Grounding DINO tiny | M2で実装・評価済みの唯一の手法。精度が十分という採用ではなく、モデル由来の候補として使用する |
| 通常の陰影補正 | `none`（補正なし） | Gray-Worldは全体とsol-correctで改善方向が一致しない。材質色の真値は得られていない |
| Intrinsic | 通常処理へ不採用、評価専用 | `academic_only`。sol-correctでは一致度も悪化 |
| prep/color | 常駐計算子へ1件ずつ渡す | #39の計算速度と失敗jobだけの再試行を両立。16/64件の一括返却は不採用 |

SAM 2.1 tiny・DINO tinyの重みはともにApache-2.0、`license_class=open`。
補正なし・Gray-Worldには重みがなく、独自の重み区分は追加しない。実際のrunには入力の制約を伝播するため、
採用モデルがopenでも全入力・全runがopenになるわけではない。
SAM 3.1は独自SAM Licenseの`restricted`で、ユーザー判断により未評価・実行経路なし。
Intrinsicのv2.0 `stage_0.pt`〜`stage_3.pt`は`academic_only`を維持する。
既存の確認結果（2026-11-02）を再利用し、ライセンスの再取得・再調査は行っていない。
出典：[segment「採用する既存実装」「重みのライセンス」](segment.md)、
[shade「Intrinsic（評価専用）」「sol判定による最終比較」](shade.md)。

M3では、公開正解の対応領域・ラベル別指標と自前写真の誤検出・はみ出しを分けて再評価する。
特に細部装飾と壁の過剰検出を改善し、未調整の評価画像でも改善することを採用変更の条件とする。
閾値・プロンプト等を調整する集合と評価集合を分け、数値の合格閾値はM3の設計で先に決める。
補正の採用変更には建築・部位・日照条件を広げた同一集合での比較と、利用条件の適合が必要。
人手正解の作成は前提にしない。現時点で装飾精度や一般的な材質色推定の品質を保証しない。

## 4. 同一建築の推定色一致度と部位間関係

出典：[shade「sol判定による最終比較（2026-11-03）」](shade.md)、

| sol-correctのみ | 3 | 4 | 8 | 0.084546 | 0.080250 | 0.133336 |

値は建築間平均ΔE_ok（L=0〜1、小さいほど一致）。wall_main / roof_surface / door / window_frameを対象に、
各由来で3手法共通の画像対→部位→建築の順に平均する。
correct領域の選別は部位平均の前に行い、複数領域は有効画素数で加重平均する。
sol-correctの比較可能部位はDomeのdoor/window_frame、Dülmenのroof_surface、Münsterのwindow_frameで、壁はない。
母数の違う由来間の数値差を選別の改善効果とは扱わない。

Gray-Worldは補正なし比でmodel全体が約3.53%悪化、sol-correctが約5.08%改善。
Intrinsicはmodel全体が約2.99%改善、sol-correctが約57.71%悪化した。
よって通常処理は補正なしを維持する。少数群・偏った部位・画角・日照面・材質・経年変化と分割誤りが残る。
画像対は独立標本ではなく、材質色の真値からの誤差や統計的に確立した優位性は示さない。
初回のbootstrap区間を最終群へ流用しない。

#45は各部位の最大クラスタ主色を代表とし、UUID順の全領域組合せを`co_occurs`として登録する。
ΔL・ΔC・Δh・ΔE_ok・面積比B/Aを記録し、隣接・包含・上下関係は推定しない。
無彩色のΔhと接地・頂部不明のnormalized_heightはNULL。
shadeの領域平均とcolorの最大クラスタ主色は集約法が異なる。
実装と検証の正本は[color「部位入力（Issue #45）」](color.md)と`tests/test_part_color*.py`。
大規模データでの部位間関係の品質評価とDB込み速度・容量は未計測。ファイル計算性能の500 assetサンプルは§5に示し、実装接続・品質評価と区別する。

この混在と稼働中の収集・I/O競合を含む実運用値で、現release単独のベンチマークとはしない。
GPU指標はCPU処理のため対象外、実運用のCPU RSSは既存記録から得られず未計測。

## 6. 10万枚・100万枚への試算

§5の実画像の実測値による、同じ入力分布・同じ1計算プロセス・再試行なしの線形外挿。
枚数N、実測件数n、実測秒S、出力byte Bに対し、時間h=N×S/n/3600、容量GB=N×B/n/10^9。
表示時だけ丸める。ubuntu-1は成功run記録時間、ubuntu-2は初期化を除いた計算・出力時間である。
処理出力のNは成功件数、rawのNは収集asset数を想定する。
ubuntu-2は失敗試行の時間も含む経過秒を成功枚数で割り、成功出力のスループットを外挿する。
固定した入力N枚の全件成功や、失敗原本を再試行で回復できることは仮定しない。

| 時間の対象（根拠は§5の各JSON） | 秒/枚 | 10万枚（時間） | 100万枚（時間） |
| --- | ---: | ---: | ---: |
| ubuntu-1 prep（全体） | 1.598911 | 44.41 | 444.14 |
| ubuntu-1 color（全体） | 0.463162 | 12.87 | 128.66 |
| ubuntu-2 prep | 0.499776 | 13.88 | 138.83 |
| ubuntu-2 segment（26句・常駐） | 8.752478 | 243.12 | 2,431.24 |
| ubuntu-2 shade none | 1.179156 | 32.75 | 327.54 |
| ubuntu-2 shade gray-world | 1.213098 | 33.70 | 336.97 |
| ubuntu-2 color（全体＋部位＋共起） | 2.922937 | 81.19 | 811.93 |

ubuntu-2で採用する補正なしの処理順はprep→segment→shade none→部位color。
各stageを直列に実行する場合に限り該当4行を加え、プロセス起動ごとに共通importとモデル初期化を1回加える。
Gray-Worldは比較用の追加処理で、採用経路の所要時間へ重ねて加えない。
CPU/GPU並列化、サービス待機、再試行、転送、実機の熱・他負荷の変化は外挿でモデル化しない。
DB関連処理はubuntu-1のrun記録範囲内だけを含み、ubuntu-2の計算ベンチには含まれない。
本番の全経過時間やSLAとは扱わず、句数・検出数・解像度・入力分布が変われば再計測が必要。
特に[prep.register](../src/colorstats/analyze/prep.py)は全assetを取得・比較するため、
DB増量に伴って1件の登録コストも増える。ubuntu-1の行は観測期間の平均を固定した参考値であり、
この走査コストの増加や複数worker間のロック競合を含む10万枚・100万枚の実時間は未確定。

| 容量の対象（成功出力の論理byte） | byte/枚 | 10万枚（GB） | 100万枚（GB） |
| --- | ---: | ---: | ---: |
| raw（500 assetの重複込み論理量） | 5,995,326.9 | 599.533 | 5,995.327 |
| ubuntu-1 prep（全体） | 60,297.8 | 6.030 | 60.298 |
| ubuntu-1 color（全体） | 6,185.6 | 0.619 | 6.186 |
| ubuntu-2 prep | 60,462.0 | 6.046 | 60.462 |
| ubuntu-2 segment（26句・常駐） | 155,650.9 | 15.565 | 155.651 |
| ubuntu-2 shade none | 84,307.0 | 8.431 | 84.307 |
| ubuntu-2 shade gray-world | 84,344.0 | 8.434 | 84.344 |
| ubuntu-2 color（全体＋部位＋共起） | 370,471.7 | 37.047 | 370.472 |

rawは選定した500 assetごとの原本byteを重複込みで加算し500で割った値。
SHA重複排除後の全量容量を、サンプルの445/500という比率だけで推定しない。
cacheの実測保持量は§5に示し、150GB cacheを全rawのミラーに使う試算ではない。
ubuntu-1/ubuntu-2のprepは配置を選ぶ代替値で、同じ出力の全量複製を前提に両方加算しない。
補正2方式の両出力を保持する場合だけ両行を加える。部位color JSONは全体観測と共起関係も含む。

DB増分・Parquet・重み・バックアップ世代・一時出力・レプリカ・filesystem overheadは未計測。
旧M1のDB増分26,222,592 byte/755 assetはM2のregion/relationを含まないため今回の外挿へ使わない。
未計測分があるため全体の必要容量・ディスク台数は確定しない。
